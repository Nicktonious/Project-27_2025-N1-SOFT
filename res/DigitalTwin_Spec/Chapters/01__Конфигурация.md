# Аппаратная конфигурация аппарата (Config) {#config}

Документ описывает структуру и состав топиков раздела конфигурации (`Config`) цифрового двойника аппарата на MQTT-брокере.

* **Политика публикации:** `retained = true` (публикуется однократно при инициализации аппарата НУ).
* **Назначение:** Описывает структуру физического оборудования аппарата (модели и параметры БП, сетевых адаптеров, адреса шины Modbus, типы секций, геометрию ячеек хранения).
* **Источник данных:** Формируется АСУ Нижнего Уровня (НУ) в процессе инициализации аппарата на основе конфигурационного манифеста `MachineConfig`. Значения топиков используются всеми уровнями системы (ВУ, СУ, НУ) для настройки драйверов, маппинга физических каналов, шин питания и топологии секций.

---

### Условные обозначения и структура колонок

* **Префикс топика:** базовый путь MQTT до узла данных. Полный топик формируется конкатенацией префикса и суффикса: `ПолныйТопик = Префикс + ТОПИК`.
* **Плейсхолдеры в фигурных скобках:**
  * `{machineId}` — уникальный строковый идентификатор вендингового аппарата;
  * `{sectionId}` — строковый или числовой идентификатор секции (`0`, `1` или `1`, `2`);
  * `{busId}` — идентификатор силовой шины электропитания (например, `BUS-1`, `BUS-3`);
  * `{psuId}` — строковый идентификатор блока питания (`PWR3`, `DRS2`);
  * `{upsId}` — строковый идентификатор модуля ИБП (`UPS1`, `UPS2`);
  * `{sensorId}` — строковый идентификатор датчика климата (`DVT-HYGROMETER`);
  * `{channelName}` — имя измерительного канала датчика (`Temp`, `Hum`);
  * `{gatewayId}` — строковый идентификатор сетевого шлюза (`icpdas1`, `ICP-CON2`);
  * `{fieldBusId}` — идентификатор полевой шины (`RS485-1`, `CAN-1`);
  * `{ioId}` — идентификатор платы модуля ввода-вывода (`IO-1.1-SPIRAL-ROW`);
  * `{camId}` — идентификатор видеокамеры (`CAM1`, `CAM2`).
* **Политика обновления (колонка ОБНОВЛЕНИЕ):**
  * `const` — постоянная конфигурационная величина, публикуется при старте в режиме Retained и сохраняется в брокере.
* **Права доступа (колонки НУ и ВУ):**
  * `W` — запись в топик (Write, публикует нижний уровень при старте);
  * `R` — чтение топика (Read, подписка верхнего уровня).

| ТОПИК | ЗНАЧЕНИЕ | ОПИСАНИЕ | ОБНОВЛЕНИЕ | НУ | ВУ |

### 6.3. Полевые шины CAN и MODBUS/TCP

* **CAN (`Field/CAN/{busId}/`):** `ID`, `Master`, `Port` (интерфейс, например `can0`), `Bitrate` (число бит/с, например `250000`).
* **TCP (`Field/TCP/{busId}/`):** `ID`, `Host`, `Port`.

### 6.4. Спецификация полиморфного блока подключения (Control)

Блок `Control` конфигурирует рабочий протокол связи АСУ с ведомым устройством (`IO`, `Env`, `PSU`, `UPS`). В зависимости от значения `Protocol` задаются соответствующие реквизиты адресации:

```json
"Control": {
  "Protocol": "ModbusRTU" | "ModbusTCP" | "HTTP" | "CAN",
  "Bus": "RS485-1",
  "Address": 41,
  "IP": "10.130.1.41",
  "Port": 502,
  "SSEPath": "/events"
}
```

* **Вариант 1. Modbus RTU (линия RS-485 через локальный порт или шлюз):**
  * `Protocol`: `"ModbusRTU"`
  * `Bus`: строковый идентификатор шины из `Field.RS485` (например, `"RS485-1"`, `"RS485-9"`)
  * `Address`: числовой Modbus Slave ID (например, `41`, `128`)
* **Вариант 2. Modbus TCP (Ethernet без промежуточной шины RS-485):**
  * `Protocol`: `"ModbusTCP"`
  * `IP`: IP-адрес Modbus-сервера устройства (например, `"10.130.1.41"`)
  * `Port`: сетевой порт Modbus TCP (по умолчанию `502`)
  * `Address`: числовой Unit ID / Slave ID (обычно `1` или `255`)
* **Вариант 3. HTTP (REST API / Server-Sent Events по Ethernet):**
  * `Protocol`: `"HTTP"`
  * `IP`: сетевой IP-адрес веб-сервера устройства
  * `Port`: сетевой порт (например, `80`, `8080`)
  * `SSEPath`: относительный URL-путь к каналу событий (например, `"/events"`)
* **Вариант 4. CAN / CANopen:**
  * `Protocol`: `"CAN"`
  * `Bus`: строковый идентификатор шины из `Field.CAN` (например, `"CAN-1"`)
  * `Address`: числовой идентификатор узла Node ID (например, `12`)
