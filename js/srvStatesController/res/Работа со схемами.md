# Работа с JSON Schema и генерацией TypeScript-типов

В данном модуле валидация данных и статическая типизация построены на концепции **Single Source of Truth (Единый источник правды)**:
1. Все структуры данных и контракты сначала описываются в формате **JSON Schema** в каталоге [js/srvStatesController/schema](file:///S:/nikita.umnov/Project-27_2025-N1-SOFT/js/srvStatesController/schema).
2. С помощью утилиты `json2ts` ([json-schema-to-typescript](https://github.com/bcherny/json-schema-to-typescript)) схемы транслируются в строгие интерфейсы и типы TypeScript в каталог [js/srvStatesController/ts](file:///S:/nikita.umnov/Project-27_2025-N1-SOFT/js/srvStatesController/ts).

> [!WARNING]
> **Никогда не редактируйте вручную файлы в папке [js/srvStatesController/ts](file:///S:/nikita.umnov/Project-27_2025-N1-SOFT/js/srvStatesController/ts)!**
> Все изменения будут автоматически перезаписаны при следующем запуске генератора. Изменения должны вноситься исключительно в соответствующие схемы `.schema.json`.

## 2. Доступные скрипты в [package.json](file:///S:/nikita.umnov/Project-27_2025-N1-SOFT/package.json)

Для генерации типов используются следующие команды:

```bash
# Сгенерировать типы только для конфигурации автомата (IMachineConfig.ts)
npm run gen:config

# Сгенерировать типы только для мониторинга (IGlobalMonitoring.ts)
npm run gen:monitoring

# Сгенерировать типы только для состояний машины (IGlobalStates.ts)
npm run gen:states

# Сгенерировать ВСЕ типы за один проход
npm run gen:all
```

## 3. Разбор параметров запуска `json2ts`

Каждый скрипт в [package.json](file:///S:/nikita.umnov/Project-27_2025-N1-SOFT/package.json) имеет следующую структуру параметров:

```bash
json2ts <путь_к_входной_схеме> <путь_к_вых_файлу> --cwd=<путь_к_папке_схемы> --enableConstEnums=false
```

* `--cwd`: указывает рабочую директорию, относительно которой резолвятся ссылки `$ref` на дочерние схемы (например, ссылки из `machine_config.schema.json` на `camera.schema.json`, `sections.schema.json` и др.).
* `--enableConstEnums=false`: отключает создание `const enum`, генерируя стандартные TypeScript `enum`. Это необходимо для того, чтобы перечисления можно было безопасно использовать в runtime и при транспиляции без ограничений изоляции модулей (`transpileOnly`, Babel, tsx).

## 4. Алгоритм внесения изменений в схемы

1. **Редактирование схемы:**  
   Найдите нужный файл в подпапке [js/srvStatesController/schema](file:///S:/nikita.umnov/Project-27_2025-N1-SOFT/js/srvStatesController/schema) (`MachineConfig`, `MachineMonitoring` или `MachineState`) и добавьте/измените поля или типы.
2. **Перегенерация:**  
   Выполните в терминале команду для обновленной схемы (или `npm run gen:all`).
3. **Проверка типов:**  
   Откройте соответствующий `.ts` файл в [js/srvStatesController/ts](file:///S:/nikita.umnov/Project-27_2025-N1-SOFT/js/srvStatesController/ts) и убедитесь, что новые интерфейсы и типы сформированы корректно.
4. **Использование:**  
   Импортируйте сгенерированные интерфейсы в сервисах и контроллерах.
